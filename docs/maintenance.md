# Maintenance

Keep documentation and dependencies current as the monorepo changes.

## Documentation maintenance

Update documentation in the same pull request as the related change.

Documentation should be reviewed when you:

- Add, remove, or change Nx targets or defaults.
- Change CI/CD workflows.
- Add or rename a plugin or theme.
- Change release, versioning, Composer, or deployment behaviour.

For project-specific changes, update documentation under:

```text
plugins/<plugin-slug>/docs/
themes/<theme-slug>/docs/
```

For monorepo-wide documentation, update the appropriate page under `docs/`.

### Editing documentation

- Edit monorepo documentation under `docs/`.
- Edit package documentation under the package's `docs/` directory.
- Use `pnpm docs:dev` to preview documentation locally.
- Update `docs/.vitepress/config.mts` when a new top-level page requires navigation.
- Do not edit `docs/content/`. It is generated by `tools/sync-docs.mjs`.


## Dependency maintenance

Dependabot manages npm and Composer dependency update pull requests through `.github/dependabot.yml`.

Current schedules are:

- npm: daily
- Composer: weekly on Monday

Dependabot allows up to three open pull requests per ecosystem. Reviews are assigned to `@bcgov/digital-engagement-solutions-custom-web`.

### WordPress dependencies

Production WordPress is currently `6.7.4`.

Shared `@wordpress/*` versions are managed through the `pnpm-workspace.yaml` catalog using `wp-6.7` releases. Updates to these packages must remain compatible with the production WordPress version.

Do not merge a dependency update when:

- CI fails because of the update.
- The dependency requires a newer WordPress version than production.
- The update otherwise introduces an identified compatibility issue.

### Reviewing Dependabot updates

For each Dependabot pull request:

1. Review the dependency change and applicable release notes.
2. Confirm compatibility with the current WordPress version where applicable.
3. Review CI results.
4. Merge compatible updates.
5. Defer updates that cannot yet be safely merged.

Prioritize critical and high-severity security updates.

Security alerts are available in the repository's [Dependabot security alerts](https://github.com/bcgov/bcew-monorepo/security/dependabot).

### Deferring an update

When a dependency update cannot be merged:

1. Close the Dependabot pull request.
2. Create an issue documenting:
   - the dependency and version
   - why the update is blocked
   - what must change before it can be updated
3. Add an `ignore` entry to `.github/dependabot.yml` and reference the issue.
4. Remove the `ignore` entry and close the issue when the dependency can be updated.

Example:

```yaml
ignore:
  - dependency-name: "@wordpress/block-editor"
    # Deferred: #123 — requires a newer production WordPress version.
    versions: ["14.0.0"]
```
